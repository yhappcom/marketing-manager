## Latest validated addition — 119
Canonical principle: **A Store-native experiment may choose the Store treatment; it does not by itself choose the best business treatment.** Google Play Store Listing Experiments can currently target unique-user install clicks, open clicks, or pre-registration clicks; Apple PPO evaluates product-page conversion using built-in Bayesian analysis and labels better/worse treatments at 90% confidence when sufficient evidence exists. Neither native result proves specialist first value, useful return, or sustainable ad-bearing use.

AK0–AK5 governs experiment objective alignment. AK0 is harmful/misleading metric optimization. AK1 is install/conversion-winner adoption without downstream evidence. AK2 has correct native experimental discipline but unknown specialist utility. AK3 requires an explicit specialist-intent hypothesis, preselected target metric, sample/duration feasibility, no noisy early winner declaration, existing first-value/useful-return definitions, downstream non-deterioration check where observable, and a decision label that distinguishes Store winner from business-compatible winner. AK4 adds observed downstream utility alignment without unsupported causal claims. AK5 is a reusable portfolio experiment registry.

Sparse niche traffic is an experimental budget. Do not fragment MintTap or LogMate traffic across weak variants merely because the Store allows them. Prefer a few decision-relevant, materially different hypotheses over cosmetic micro-tests. On Google Play, open clicks can be a better native target than install clicks when initial engagement matters, but an open is still not first value.
