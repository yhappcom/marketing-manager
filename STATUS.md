## Latest validated addition — 107
Canonical principle: **Treat locale fallback as an active distribution path. A market/language is safe only when the exact Store experience users can receive — authored localization, platform fallback, or automated translation — stays within the production claim ceiling.**

This closes an operational gap left after 091/105: `not localized` does not mean `not marketed`. Apple can select the next relevant/primary localization based on storefront and language settings, and app previews can fall back to another available language. Google Play default listings can offer automated translations when the publisher has not supplied one, but Google Custom Store Listings are explicitly not automatically translated; without publisher translations, a targeted CSL can be shown in its default language.

Therefore Apple fallback, Google default-listing machine translation, and Google CSL default-language exposure are separate states. Country and language must not be collapsed into one localization flag.

Z0–Z5 governs this layer. Z3 is the minimum deliberate market-expansion threshold: actual served path mapped and tested, specialist terminology/claims within production evidence, material visual/video language validated, and fallback incapable of overstating the product.

Required registry:
`app → platform → storefront/country → user_language → page_type(default/CPP/CSL) → authored_locale → served_fallback_rule → auto_translation_possible → text_claim_version → screenshot/video_locale → specialist_term_ledger_version → currency/units → support/privacy parity → production_version → last_verified → stale_trigger → Z-class`

MintTap must human-validate financial terms such as ROC, distribution, tax adjustment, cost basis, return and reverse-split semantics before deliberate locale targeting. LogMate must do the same for block/flight time, PIC/SIC, IFR/instrument, takeoff/landing, roster/import and offline/backup claims. Platform machine translation is not specialist claim evidence.
