## Latest validated addition — 117
Canonical principle: **Apple Custom Product Page keywords are an intent-routing capability, not a proven ranking boost. Use them only when a materially different specialist query/job deserves different truthful Store evidence.** Apple documents that CPPs can be assigned keywords so the matching CPP can appear in App Store search instead of the default page, requires keyword/page intent match and unique keyword combinations per CPP, supports up to 70 CPPs, independent metadata review, localization, per-page analytics and optional deep links.

AI0–AI5 governs CPP search routing. AI0 is manipulation/irrelevant or unsupported claims. AI1 is page/keyword coverage chasing. AI2 has plausible segmentation but incomplete evidence. AI3 requires a materially distinct specialist job, unique keyword ownership, production-valid page evidence, Z3+ locale parity, safe intent continuity, measurement discipline and stale/retirement ownership. AI4 requires observed qualified routing plus downstream first value/useful return. AI5 is a reusable portfolio registry.

For MintTap, do not create ticker-by-ticker CPPs merely by substituting CONY/MSTY/TSLY. Candidate families such as portfolio/distribution tracking, ROC/tax-adjustment accounting, and reverse-split/cost-basis continuity must first demonstrate distinct demand and shipping evidence. For LogMate, defer CPP search routing until production scope and pilot first-value evidence stabilize.
