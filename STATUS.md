## Latest validated addition — 142
Canonical finding: **MintTap release 1.0.29 already contains live banner inventory, but the first audited placements are not yet decision-grade revenue surfaces. Implementation-policy drift and measurement gaps must be resolved before optimization.**

The production-relevant evidence is on release branch `1.0.29`, not default `main`; monetization audits must preserve the exact release ref. Two placements are directly confirmed. MT-AD-P1 is a non-browse Home inline adaptive mobile banner. It is reconstructed after return from stock detail via a refresh-token key and has no explicit cap/cooldown or paid-event callback in the widget. This conflicts with the later Home-ad-free product direction, so optimization is frozen pending reconciliation/removal. MT-AD-P2 is a non-browse stock-detail anchored adaptive fixed-bottom banner. Its key changes with the selected detail tab, so tab switching reconstructs the slot and can create additional request opportunities. It also lacks an explicit cap/cooldown and paid-event callback in the audited widget.

The 1.0.29 tree also contains generic adaptive-inline banner components, web AdSense components, privacy/consent infrastructure and app-ads.txt, but these remain `unmapped`, not `inactive`, until screen-level use is directly recovered.

Research 142 creates the first live AM–AR+BF+BG registry slice and establishes a new evidence rule: **widget lifecycle/remount behavior is part of the ad exposure denominator. Extra requests caused by navigation or tab reconstruction must not be mistaken for user demand or intentional inventory.** No new ad format should be added before existing banners are measurable and reconciled.

## Progress interpretation
A zero-cost channel is not successful because it generates clicks, followers or installs. An owned blog is not successful because it publishes many pages or accumulates impressions. A consequential financial claim is not trustworthy merely because it comes from an official-looking page; authority must match the exact claim and provisional estimates must remain provisional. A Store treatment is not successful merely because a platform reports a better conversion number. Missing/censored evidence is not zero. An ad system is not successful because it maximizes impressions, eCPM or short-run revenue; success requires incremental reconciled revenue from natural eligible states without material degradation of core value. An impression-level revenue value is not decision-grade merely because an SDK emitted it. **A code audit is also not decision-grade unless it names the production/release ref: stale default branches can produce false absence, while widget remounts can create false inventory signals.** Optimize qualified retained/reactivated specialist utility, evidence integrity, community trust and sustainable reconciled revenue—not content volume, top-of-funnel volume or raw ad inventory.
