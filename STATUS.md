## Latest validated addition — 285
Community marketing is a permissioned trust surface, not free distribution. Reddit's current guidance says promotional content is not inherently spam, but communities may prohibit promotion or use their own conventions, and moderators decide what is unwanted. Repetitive/cross-community promotion, link farming, unsolicited bulk messages, and business-link-heavy participation remain material spam risks.

GL0–GL8:
community fit → current rule audit → native-value test → interest disclosure → link necessity → repetition control → trust ledger → distribution gate → re-entry trigger.

Preserve: a “10% self-promotion rule” is not a platform-wide entitlement. Community rules/moderator judgment outrank numeric frequency. A useful native contribution that generates zero installs can still be successful marketing when it produces specialist trust, language, product evidence, or a durable reference asset.

## Latest validated addition — 294
A meaningful specialist-app repair is not complete when code ships. Synchronize the verified fix only across surfaces whose prior claim, workaround, or expectation became stale: release notes, affected review responses, support, Store claims, owned references, and permitted community follow-up. Apple explicitly recommends release-note disclosure plus replies to relevant older reviews after a fix; significant product changes require specific What’s New text. Rating reset is not a repair substitute and should be used sparingly.

GU0–GU9: evidence anchor → repair verification → release-note specificity → affected-review closure → support synchronization → Store-claim synchronization → owned-reference synchronization → community re-entry gate → repair measurement → close/reopen.
