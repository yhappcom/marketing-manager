## Latest validated addition — 234
Google Play organic visibility is partly constrained by technical quality, not only Store metadata. Android vitals identifies core quality metrics that affect Play visibility. Current documented bad-behavior thresholds include user-perceived crash rate (1.09% overall / 8% per phone model), user-perceived ANR rate (0.47% overall / 8% per phone model), and excessive partial wake locks (5% overall). Play evaluates quality on a trailing 28-day basis, and device-specific failure can matter independently of the overall average.

Google announced on 2026-08-26 that from February 2027 Play will enforce bad-behavior thresholds for dynamic memory usage (Anonymous RSS + Swap), bitmap memory usage, and DEX code optimization. Apps/games failing them may see reduced visibility and publishing capabilities. Memory evaluation varies by device RAM tier and app state; it is not one universal MB ceiling. Current Android vitals documentation also specifies a 25% minimum DEX optimization/obfuscation/shrinking threshold for apps with >10 MB DEX code.

This visibility relationship is already operational for battery behavior: since 2026-03-01, titles above the excessive partial-wake-lock threshold may be excluded from prominent discovery surfaces and may receive a Store warning.
