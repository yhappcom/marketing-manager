## Latest validated addition — 168
Native ads are a distinct integrity problem because the app receives ad assets and renders them through its own UI. Better visual fit must not collapse the boundary between paid inventory and product/editorial content.

Google requires explicit ad attribution and visible AdChoices for programmatic native ads. Native-ad objects have their own lifecycle: bound caching/preloading, no uncontrolled retry loops, and destruction when unused/replaced. Cached/loaded inventory is not an impression or revenue event.

Google's Native Ad Validator can check test-ad implementations before release. Treat validator success as implementation/policy evidence only; it is not proof that the placement is appropriate for a professional workflow or that user value is preserved.

CF0–CF5: `surface eligibility → advertisement identity → layout/click integrity → object/cache lifecycle integrity → pre-release validation/observability → sustainable-value decision`.

Canonical chain: `eligible secondary surface → explicit ad identity → stable low-risk template → bounded request/load/cache lifecycle → actual render/impression → paid-event/reconciliation → preserved repeated useful value`.

Preserve `native request ≠ loaded object ≠ rendered ad ≠ impression ≠ paid callback ≠ precise/reconciled revenue ≠ sustainable incremental value`, `validator pass ≠ product appropriateness`, and `preloaded object ≠ exposure`.

For MintTap and LogMate, native styling must never make paid content resemble financial records/insights, flight records, operational/compliance status, warnings, authoritative guidance, or core product recommendations. Do not introduce native inventory merely because it can visually blend into the product.

## Progress interpretation
Zero-cost success is not clicks, followers, karma, pre-registrations, pre-orders or installs. Native attribution improves observability but not incrementality. Sparse evidence remains inconclusive. Accessibility is a product capability first and discovery surface second. Store/platform approval or metadata is not proof of demand or product-market fit. Ad supply authorization is not revenue proof; a native request/load is not an impression, a banner request is not an impression, a collapsible request is not necessarily an expanded exposure, a reward offer is not an opt-in, an impression/dismissal is not an earned reward, and an impression-level paid event is not necessarily precise or reconciled revenue. Validator success is not proof that an ad placement preserves product value. Higher request/refresh volume, excessive native density, repeated expanded overlays, coerced rewarded views, or short-term ad yield is not sustainable growth if it degrades core-task completion or repeated useful value. Sustainable growth requires qualified users to reach and repeat promised core value while advertising adds reconciled incremental revenue only from clearly identified, natural or genuinely voluntary states that do not materially degrade that value.
