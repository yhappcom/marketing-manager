# Research 250 — Visual/Multimodal Search as a Zero-Cost Specialist Demand Sensor

Status: validated
Date: 2026-09-25

## Why this matters

Google Search Console added a dedicated web multimodal search type on 2026-09-24. It reports web discovery originating from Lens, Circle to Search on Android, image uploads to Google Search, and Chrome's image-search flow. For a zero-paid-media niche-app portfolio, this creates a newly observable acquisition surface rather than a reason to manufacture image content.

## Validated platform facts

1. Search Console is rolling out a global multimodal-search filter in Search Results performance reporting and Generative AI feature reporting. Metrics appear when a site receives traffic from those queries.
2. Google recommends normal image-search fundamentals: crawlable/indexable landing pages and image URLs; standard HTML img/src rather than CSS background images for discovery; responsive images with a src fallback; high-quality but performant assets; descriptive contextual text, filenames and alt text; and image sitemaps when useful.
3. Landing-page context matters. Google explicitly says key information should remain in text rather than only inside graphics. Alt text and computer vision help Google understand images, but visual assets are not a substitute for a useful textual page.
4. A preferred representative image can be signaled with primaryImageOfPage/main-entity image markup or og:image. Structured data must match visible content and does not guarantee a search feature.

## FM0–FM5 Visual Demand Integrity Gate

FM0 — Demand identity: define the specialist question/job the visual solves before producing an asset.
FM1 — Standalone utility: the visual must make a real concept, workflow, comparison, or data relationship easier to understand; decorative production does not qualify.
FM2 — Crawl/context integrity: the image and landing page must be accessible, indexable, technically discoverable, and accompanied by useful textual context.
FM3 — Promise continuity: image/search interpretation → landing-page claim → Store/product capability must describe the same job. Never imply financial outcomes, regulatory/compliance guarantees, or unsupported automation.
FM4 — Measurement integrity: separate multimodal impressions/clicks from ordinary web/image traffic when Search Console exposes the data; preserve page/query/device/country context where available. A click is not activation.
FM5 — Qualified-value decision: scale only when multimodal discovery produces useful specialist engagement and, where measurable, qualified Store/product progression or reusable demand insight.

## Portfolio application

### MintTap

Good candidate visual classes are explanatory, not promotional: split-adjusted distribution-history diagrams, ROC/distribution methodology illustrations, and portfolio-tracking workflows where a graphic genuinely clarifies the underlying concept. Ticker-by-ticker near-duplicate image/page generation is not a growth strategy. Each indexed landing page must justify itself with distinct specialist utility and textual context.

Do not treat a screenshot of an ETF table as evidence that Google understands or endorses the investment information. Keep material facts in accessible text and maintain the existing financial-promise discipline.

### LogMate

Potential visual assets include logbook migration/import maps, field-mapping examples, reconciliation workflows, and product-supported logging concepts. Avoid presenting visual checklists as regulatory authority or implying compliance/recency conclusions beyond verified product scope. Visual discovery must route to a page that explains the same pilot job in text.

## Measurement ledger

For each candidate page record:
- specialist job and intended visual question;
- canonical landing URL and image URL;
- asset type and why visual treatment is necessary;
- indexability/crawl checks and representative-image metadata;
- multimodal impressions/clicks when available;
- ordinary Search/Image traffic separately;
- downstream Store referral/activation evidence where observable;
- recurring language/questions discovered;
- keep/revise/retire decision.

## Prohibited inferences

- multimodal reporting available ≠ the site currently has multimodal demand;
- more images ≠ more organic growth;
- image impressions ≠ qualified demand;
- visual click ≠ Store install or repeated product value;
- computer vision ≠ permission to hide key information inside graphics;
- structured data ≠ guaranteed rich/visual appearance;
- a visual-search spike ≠ proof that the image itself caused conversion;
- niche SEO ≠ permission to mass-produce near-duplicate ticker, route, aircraft, or template pages.

## Operating decision

Treat multimodal Search as a measurement opportunity first. Build only a small set of high-utility visuals attached to already justified specialist pages, establish a baseline, and inspect Search Console's multimodal filter before scaling production. Reuse validated demand language in blog/Store/community surfaces only when the promise remains truthful and audience-native.
