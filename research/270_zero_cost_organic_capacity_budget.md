# Research 270 — Zero-Cost Organic Capacity Budget

Validated: 2026-09-27

## Decision

For sparse professional apps, "zero-cost marketing" must be budgeted as scarce operator attention, not treated as unlimited distribution. The unit of allocation is not posts/week. It is **operator minutes per independently validated specialist problem that produce decision-useful evidence or qualified/repeated product value**.

## Current authoritative constraints

- Reddit Rule 2 requires authentic participation, compliance with each community's rules, and prohibits spam/disruptive content manipulation. This makes repetitive cross-community distribution structurally risky, not merely inefficient.
- Reddit's Jan–Jun 2025 transparency report says spam remained the majority (57.5%) of admin removals. Scale therefore cannot be the default optimization target for unpaid community distribution.
- Reddit's Moderator Code of Conduct, effective 2025-06-05, requires active/consistent moderation and integrity. An owned subreddit therefore creates an ongoing operating obligation; opening more branded communities is not free reach.
- Google Play now centralizes reusable creative assets across main listings, custom listings, experiments and events. Reuse is operationally valuable, but reusable assets do not justify multiplying surfaces without distinct validated intent.

## FO0–FO8 Organic Capacity Gate

1. **FO0 — Specialist problem truth:** name the recurring job/problem before choosing a channel.
2. **FO1 — Independent evidence:** distinguish one anecdote from repeated independent observations.
3. **FO2 — Surface fitness:** choose the surface where the audience naturally solves that problem.
4. **FO3 — Native completeness:** the contribution should provide value on the surface without requiring a click.
5. **FO4 — Maintenance burden:** estimate reply, moderation, correction, update and measurement time.
6. **FO5 — Incremental value:** a second surface is allowed only when it adds a distinct function, audience or durable artifact.
7. **FO6 — Destination continuity:** links are justified only when the destination materially continues the same specialist job.
8. **FO7 — Downstream evidence:** prefer qualified activation, restored/repeated core value and new independent evidence over impressions/followers/karma.
9. **FO8 — Stop/reallocate:** reduce or stop a pattern that repeatedly consumes attention without producing new evidence or downstream specialist value.

## Capacity ledger

Track each recurring organic activity with:
- app / specialist_job_id
- surface
- activity type
- operator minutes
- moderation/reply minutes
- maintenance/update minutes
- independent evidence gained
- qualified Store/app visits where measurable
- first core value
- repeated/restored core value
- durable reusable asset created
- policy/community-rule risk
- decision: KEEP / REDUCE / STOP / MOVE / HOLD

Do not fabricate precision where attribution is unavailable. Minutes and evidence class can be recorded even when installs cannot be causally assigned.

## Allocation rule

Default order for a new validated problem:
1. answer/help where the audience already discusses it;
2. preserve durable explanation/calculation evidence on owned web only when recurrence justifies maintenance;
3. route to Store/product only when the app materially continues the same job;
4. use social only when it adds timely conversation, evidence sensing or a genuinely different audience;
5. do not syndicate the same artifact mechanically across every surface.

A calendar may reserve review time; it must not create a publishing obligation.

## MintTap application

Allocate community time to recurring YieldMax investor jobs such as distribution/ROC interpretation, corporate-action continuity and portfolio accounting. Do not create separate content quotas merely because different tickers are mentioned. Treat r/MintTapforYieldMax as an owned community with moderation cost, not free inventory. A native answer should remain useful even if the user never installs MintTap.

## LogMate application

Prioritize pilot workflow problems: migration/import, previous totals, duplicate reconciliation, record integrity, export and offline/device continuity. Generic aviation engagement is outside the growth budget unless it produces evidence for a real LogMate job. Pilot trust and accuracy outweigh posting cadence.

## Portfolio rule

Across MintTap, LogMate and future niche apps, allocate scarce organic time to the activity with the highest expected:
**independent evidence + qualified/repeated specialist value + durable reusable knowledge**
per operator hour, subject to platform/community integrity.

Do not optimize this as a single numeric score until enough observations exist. Use the ledger to expose obviously dominated activities first.

## Stop rules

STOP or REDUCE when a pattern repeatedly:
- produces only impressions, likes, followers, karma or clicks;
- duplicates an existing artifact without a distinct surface function;
- requires disproportionate moderation/correction;
- depends on promotional framing that conflicts with community norms;
- routes users to a destination that does not continue the same job.

KEEP can be justified by strong qualitative evidence even before attribution is statistically mature, but record why.

## Unresolved operational questions

- Actual weekly operator-time ceiling available for MintTap vs LogMate.
- Which MintTap community/owned-web activities currently consume the most maintenance time.
- Whether r/MintTapforYieldMax produces independent problem evidence beyond support for existing users.
- Which LogMate pilot communities permit developer participation and under what rules.
- Whether current analytics can connect external intent to first/repeated core value without privacy-invasive tracking.

## Next learning target

Build a **Community Permission & Identity Registry**: per-community rules, developer/self-promotion disclosure requirements, allowed link behavior, evidence value, moderation burden and expiry/recheck date. This converts community marketing from generic channel advice into an auditable operating system.
