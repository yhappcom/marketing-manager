# Research 315 — Search-Discoverable Social Content Contract

Validated: 2026-09-30

## Decision

For a zero-cost niche-app portfolio, selected social/video posts can be treated as a second search-discovery surface in addition to the owned website, but only when the platform/audience fit is already justified. Do not create social volume merely to obtain Google visibility.

Google introduced Search Console platform properties in July 2026 for Instagram, TikTok, X, and YouTube. Verified accounts can measure how individual social/video URLs are discovered through Google Search, Discover, and Google News, including clicks, impressions, queries, countries, and post-level performance. This turns off-site social content from an attribution blind spot into an observable discovery surface.

## Authoritative evidence

1. Google Search Central, July 7 2026: platform properties support Instagram, TikTok, X, and YouTube and expose Performance, Insights, and Achievements reports for Google discovery.
2. Google's analysis guide says platform-property data can identify top posts, search queries, country/device differences, trending query groups, 24-hour changes, and format differences; exports are supported.
3. Google explicitly recommends using observed search terms and performance to inform subsequent content, repackaging, cross-promotion, captions, hashtags, and format decisions.
4. Search Console reporting is observational. It shows how content was discovered; it does not establish incrementality or prove that posting caused downstream app adoption.

Sources:
- https://developers.google.com/search/blog/2026/07/search-console-social-video-platforms

## HQ0–HQ9

HQ0 specialist-fit gate — use a platform only if the target professional/niche audience plausibly uses it.

HQ1 atomic problem — each asset should answer one recurring specialist problem, not advertise the app generically.

HQ2 native completeness — the post/video must deliver useful value on-platform; a Store or website click is not required for the content to be worthwhile.

HQ3 search legibility — title/caption/description should use the language specialists actually use when it remains natural and accurate; do not keyword-stuff.

HQ4 platform-property measurement — where supported and owned, verify the account in Search Console and observe Google-origin impressions, clicks, queries, country/device and post-level evidence.

HQ5 query-to-intent mapping — map observed Google queries to the recurring-problem/Claim Registry taxonomy rather than treating every query as a new content topic.

HQ6 lifecycle extension — when an older asset gains renewed search traction, prefer updating, contextual follow-up, or a deeper owned reference over blindly increasing posting frequency.

HQ7 format evidence — compare formats only where the platform and audience make the comparison meaningful; e.g. long-form versus Shorts on YouTube.

HQ8 downstream separation — distinguish Search discovery, social-platform engagement, qualified transition, first specialist value, repeated specialist value, and monetization. Do not collapse them into one attribution claim.

HQ9 decision — KEEP / REPACKAGE / DEEPEN-OWNED / CROSS-PROMOTE / HOLD / RETIRE / UNKNOWN.

## MintTap application

MintTap's strongest default remains investor communities plus maintained owned references. Instagram/TikTok/X/YouTube are not mandatory merely because Search Console can measure them.

If a supported channel is tested, use recurring investor problems as the content unit: estimated vs final ROC, split/reinvestment reconstruction, broker/issuer reporting mismatch, and total-return/recovery methodology. Avoid ticker-name cloning. A search-discoverable post should be independently useful and should route to an owned reference only when the reference materially adds evidence, methodology, updateability, or depth.

Search Console platform-property evidence can answer a previously weak question: whether a social asset attracts Google search demand after the feed-distribution window has passed. That durable search discovery is more strategically valuable than raw short-lived reach for a zero-cost niche business.

## LogMate application

The fit is stronger for professional educational video where a pilot is actively solving a workflow problem. Candidate problems include logbook import/migration, duplicate reconciliation, Previous Totals continuity, export/certificate integrity, and offline/PWA/device boundaries.

YouTube is particularly testable because Search Console can compare video/Shorts URL groups and expose the queries that surface individual content. However, professional accuracy and workflow integrity outrank reach. Do not produce generic aviation entertainment solely to inflate an audience that is poorly matched to LogMate.

## Guardrails

- Platform-property data is not incrementality.
- Search Console may omit or aggregate low-volume data; absence of a visible query is not proof of zero demand.
- Search traction does not override community/platform rules or claim evidence.
- Do not duplicate the same asset across every platform by default.
- Do not create a social account solely because Search Console supports it.
- Do not optimize for impressions when the audience or downstream specialist value is wrong.

## Strategic consequence

Owned references and selected social/video assets now form a measurable two-layer zero-cost search system:

recurring specialist problem → native social/video answer and/or canonical owned reference → Google discovery evidence → qualified transition when useful → first/repeated specialist value.

The new capability changes measurement, not the underlying rule: audience fit and specialist usefulness come before channel expansion.
