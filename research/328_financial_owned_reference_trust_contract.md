# Research 328 — Financial Owned-Reference Trust Contract

Validated: 2026-09-30

## Decision
For a finance-adjacent niche app such as MintTap, owned-reference SEO is not a volume-content program. It is a trust/provenance system for recurring investor questions. Google explicitly gives stronger weight to signals aligned with E-E-A-T for YMYL topics that can affect financial stability; trust is the most important component. Search growth therefore follows verified specialist usefulness, not keyword-page multiplication.

## Authoritative findings
1. Google Search says people-first content should provide original information/research/analysis, substantial value beyond source rewriting, clear sourcing, and demonstrable expertise. It warns against mass-producing content across many topics, extensive automation for search traffic, and changing dates merely to appear fresh.
2. Google states E-E-A-T is not itself a single ranking factor, but its systems use signals aligned with experience, expertise, authoritativeness and trustworthiness; trust matters most, and stronger E-E-A-T alignment is especially important for YMYL topics affecting financial stability.
3. Google recommends making the Who, How, and Why of content clear: accurate authorship/bylines where expected; methodology/process disclosure where useful, including material automation/AI use; and a primary purpose of helping users rather than attracting search visits.
4. Discover requires no special markup and eligibility does not guarantee distribution. Google describes Discover traffic as less predictable/dependable than keyword-driven Search. It recommends non-clickbait headlines, timely or uniquely insightful content, and strong page experience.
5. Intrusive promotional interstitials—including app-install prompts—can frustrate users, erode trust, and impair Search understanding. Owned references must remain readable before any install CTA.
6. Google Search is free to appear in; no paid distribution is required for eligibility.

## ID0–ID9 contract
ID0 recurring specialist problem evidence
→ ID1 YMYL/claim-risk classification
→ ID2 primary-source/provenance bundle
→ ID3 original specialist contribution
→ ID4 Who/How/Why disclosure
→ ID5 uncertainty and jurisdiction boundary
→ ID6 content-first page / non-intrusive CTA
→ ID7 update/invalidation trigger
→ ID8 Search/Discover measurement without dependency
→ ID9 KEEP / REPAIR / MERGE / RETIRE / UNKNOWN.

## MintTap application
Priority owned references remain problem-based, not ticker-clone based:
- estimated vs final ROC and provenance;
- issuer notice vs broker/tax reporting boundaries;
- split/reinvestment reconstruction;
- total-return/recovery methodology;
- Tax Adjustment mechanics with jurisdiction/scope qualification.

Every finance-sensitive page should expose enough provenance to audit the conclusion: source type, relevant date/period, methodology, assumptions/uncertainty, and last substantive verification. A cosmetic date refresh is not an update. TSLY/CONY/MSTY/NVDY variants should be split only when the underlying evidence, workflow, methodology, or user intent materially differs.

## AI/automation rule
AI may assist drafting/restructuring, but the publishable unit is the verified claim/evidence bundle. For pages where readers would reasonably care how conclusions were produced, disclose material automation/AI involvement and methodology. Do not use automation to manufacture keyword variants or summarize sources without additional specialist value.

## Conversion rule
Owned references are complete answers first. App-install CTAs are subordinate, contextual, and non-blocking. Do not gate methodology/evidence behind an install prompt or obscure the reference with a full-screen promotion.

## Measurement
Track: query/problem class | landing page | evidence freshness | qualified Search clicks | returning reference users | Store transition | first specialist value | repeated specialist value | support deflection | correction/retraction events. Discover is opportunistic upside, not a forecastable acquisition channel.

## Reusable niche-app rule
For future specialist apps, the content moat is not publishing frequency. It is a maintained set of auditable answers that an expert user would still value if Search traffic and app-install links disappeared.
