# Research 379 — Apple CPP Keyword Routing as an Intent Portfolio

Validated: 2026-10-02

## New finding

Apple Custom Product Pages should be managed as a portfolio of distinct specialist intents, not expanded toward the platform's page-count limit. Apple currently allows up to 70 CPPs, but recommends that assigned keyword combinations be unique to each page and match that page's intent. Assigned keywords come from the latest approved app version and can cause the CPP to appear instead of the default page for those searches. CPP metadata and deep links require review. CPP performance data becomes available only after at least five first-time downloads.

## IR0–IR9

search evidence → specialist job → default-page adequacy → materially distinct promise → distinct proof/assets → unique keyword set → matching destination/deep link → review/visibility → threshold + downstream specialist value → KEEP / MERGE / REASSIGN / DISABLE / HOLD-SPARSE / DO-NOT-CREATE.

## Operating rules

1. Default-page adequacy comes first. A keyword does not deserve a CPP if the default page already serves the same job well.
2. Avoid semantic collision. Pages representing the same job, proof and destination should be merged rather than multiplied.
3. Preserve promise-to-destination coherence. A specific search promise should lead to the matching in-app job, not a generic destination where avoidable.
4. Below Apple's five-first-time-download analytics threshold, missing page metrics mean HOLD-SPARSE, not failure.
5. Seventy pages is capacity, not a KPI. Niche apps should prefer the smallest set of materially distinct intent routes.

## MintTap

Do not split CPPs merely by TSLY, CONY, MSTY or NVDY. Evaluate job-level intent first. Distribution/ROC tracking, portfolio recovery/tax-adjustment, and split/reinvestment continuity are candidate families only; each requires actual approved-keyword evidence, distinct proof, and a matching destination before creation.

## LogMate

Do not manufacture pre-launch CPPs without search evidence. After launch, import/migration, multi-leg logging, and export/continuity may qualify only when observed intent, Store proof and product destinations are genuinely distinct.

## Reusable rule

search intent → smallest truthful set of distinct Store promises → matching product destinations → first/repeated specialist value.

Every new CPP creates review, localization, analytics and maintenance obligations. It must earn that complexity through distinct intent.
